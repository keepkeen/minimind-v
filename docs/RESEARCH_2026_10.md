# 截至 2026-10-09 的多模态进展与项目取舍

检索截止：2026-10-09。重点是能影响本项目决策的一手材料，不是所有多模态论文的排行榜。日期区分模型预览、权重公开、论文提交与 arXiv 列表公告；不能把尚未发布的权重当成当前可复现基线。最新一组下列论文在 10 月 8 日提交、进入 10 月 9 日公告列表。

本次只完成资料核查和工程实现，没有复现下列论文的完整训练或接受作者性能数字为本项目实测成绩。

## 业界：任务和系统成本比单一参数口号更重要

### Mistral Large 4：2026-10-06 公共预览

[官方发布](https://mistral.ai/news/mistral-large-4/)将其描述为原生多模态模型，突出图像定位、文档/工程图与工具操作。在核查时是 API 预览，官方称权重将在月底发布，而不是已经可下载。

对本项目的启发是让答案对应可检查的视觉证据和具体操作，而不是只让 caption 更长。它的规模、训练资源和 agent 能力不能通过给 MiniMind 加一个 Web UI 等价获得。本 fork 没有调用该模型 API，也没有产生付费调用。

### MiniCPM-V4.6：2026 年端侧可用模型实例

[官方模型卡](https://huggingface.co/openbmb/MiniCPM-V-4.6)描述 SigLIP2-400M + Qwen3.5-0.8B 路线，支持混合 4×/16×视觉压缩及多种部署框架；模型卡新闻中的 2026-05-17 是 API 服务日期，不据此冒称首发日期。

启发：按任务比较多个视觉预算，并把编码器与语言侧成本分开。本 fork 的固定空间平均池化不是其架构复现，4/16/64 是输出 token 数，也不是直接照搬对方压缩率。它可作为以后真实任务的外部对照，但模型大小与训练数据不同，不能当成公平的单模块消融。

### Liquid LFM2.5-VL-DSpark：2026-09-24

[官方工程文章](https://www.liquid.ai/blog/lfm2-5-vl-dspark)讨论多模态推测解码，并明确指出它主要加速 decode，不能消除视觉编码和 prefill 成本。

启发：不再只报一个混合 tokens/s。BudgetLab 分别记录预处理、TTFT、完整生成、请求耗时和首 token 后吞吐。未来先分析瓶颈，再决定重采样、视觉缓存、量化还是推测解码；不会为了追热点给 65M 主干先加一个更贵的 drafter。

### Gemma4 12B：2026-06-03

[Google 官方介绍](https://blog.google/innovation-and-ai/technology/developers-tools/introducing-gemma-4-12b/)给出 encoder-free 的统一视觉/音频输入路线，使用轻量映射将模态输入交给主干处理。

启发：面试时不要声称“所有 VLM 必须是视觉编码器 + projector + LLM”。MiniMind 采用的是成本可控、便于学习的一种路线；这里没有替换成统一预训练架构，不能把接口接上图像称为已实现原生全模态模型。

### Qwen 系列：已核查到 2026 年 8 月发布信息

[官方仓库](https://github.com/QwenLM/Qwen3.8)列出 Qwen3.8-2.4T-A95B 的 2026-08-12 与 Qwen3.8-27B 的 2026-08-14 发布。其 Qwen3.5 介绍已强调统一图文训练与高效混合架构；小尺寸 Qwen3.5-0.8B 在 2026-03-02 的发布记录中列出。

启发：区分“小项目教学架构”和“经过大规模联合预训练的原生多模态底座”。小模型的竞争点应是确定场景下的成本与可验证性，而非声称达到同期通用模型能力。实际接入外部基线时需另建环境并遵循各自版本要求，不能强行沿用本仓库 transformers 4.57.6。

## 学术：最新论文如何改变实验问题

### 2026-10-08：OneSearch-VL，证据链成为训练和评价对象

[论文](https://arxiv.org/abs/2610.12419)把图像/视频深度检索组织为视觉定位、外部证据检索与事实组合，并使用 Visually Grounded Evidence Graph 连接这些步骤。

本项目可借鉴的是保留图片/区域 ID、问题、原始答案和评测记录，未来使字段输出可追溯。当前只实现正确图、黑图、错图的基础诊断，并没有 evidence graph、区域定位模型、联网 agent 或该论文的 RL 奖励；不能把它们列为已完成贡献。

### 2026-10-08：FastBench，视频预算是时间与空间的联合问题

[论文](https://arxiv.org/abs/2610.12427)针对高动态视频中的快速事件，考察帧率、历史长度与上下文预算之间的冲突。它提醒我们稀疏抽帧可能直接丢掉关键事件，单纯加长文本推理无法补回观察不到的信息。

本项目目前只处理图片。多图张量接口不自动等于流式视频能力；要做视频，至少需要时序信息、采样策略、事件级标注和流式延迟评测。首期不把多张图片输入包装成已经完成视频理解。

### 2026-10-08：工业异常理解中的细粒度感知瓶颈

[Is In-Domain Training Enough for Fine-Grained Industrial Anomaly Understanding?](https://arxiv.org/abs/2610.12310)研究工业异常检测、定位、描述与推理之间的能力差异，并用专门视觉专家提供细粒度证据。

本项目因此只把大尺度状态和短字段问答作为候选入口，不预设 256 分辨率小 VLM 可以代替细微缺陷检测器。应把专用 CV 模型列入对照，必要时将 VLM 放在解释/交互层，而不是要求它承担所有感知。

### 2026-10-02：P2P，不删 token 也能研究视觉计算压缩

[From Patching to Pruning Visual Computation in Vision Language Models](https://arxiv.org/abs/2610.03389)通过激活干预寻找可绕过的视觉投影计算，保持序列位置与长度不变。

本项目只做更简单的输入空间池化对照，不声称复现 P2P。重要启发是按模型层和阶段分析计算，而非把 token 数当成唯一成本指标。其推理干预也不能直接证明 MiniMind 的“只微调首尾层”策略最优。

### 2026-10-01：MMVistaReason，容量适配的数据与后训练

[论文](https://arxiv.org/abs/2610.01352)研究分阶段数据清理、按难度筛选教师轨迹以及与学生容量相关的 SFT/RL 取舍。

对 65M 语言主干更合适的研究起点是短答案或短结构化步骤的质量、难度分层与错误分析。是否采用长 CoT 或 RL 要通过数据和奖励实验决定。这里没有运行教师 API、生成蒸馏数据或实施该论文训练方案。

### 2026-10-01：Where Scaling Stops，主干和视觉预算联合选择

[Not All Error Yields to Scale](https://arxiv.org/abs/2610.01640)研究语言主干规模与视觉 token 数共同影响效果的关系。作者分析范围主要是 1B–72B 级模型，不应把其拟合定律直接当作本项目 65M 的预测器。

本项目把它转化为可检验问题：在每个任务切片上究竟是“看不清”“推理容量不足”还是“监督不足”？保留 64/16/4 的对照，再决定应该增加输入信息还是主干能力。

### 延伸阅读：视频与 VLA

[VETO，2026-10-01](https://arxiv.org/abs/2610.01785)讨论帧内和帧间两个维度的视觉 token 优化；[VLA-ACL，2026-10-06](https://arxiv.org/abs/2610.08133)将选择 token 的监督与下游动作一致性相连；[Rephrase Before You Act，2026-10-07](https://arxiv.org/abs/2610.10526)研究指令改写对 VLA 的影响。

这些是未来多模态面试的知识拓展，不是给当前项目增加机器人能力的依据。可迁移的实验习惯是任务相关监督、指令改写鲁棒性与跨场景评价。

## 从资料到可验证贡献

当前贡献是根因明确的工程修复、可解释的预算对照和可保存的评测记录。下一步最值得完成的是一份实际数据上的比较报告，而不是继续添加模块名。

每项研究结论都应能回答：使用了什么输入信息、改变了哪段计算、用什么独立数据测量、是否存在同图泄漏、代价发生在哪里、失败集中在哪些题型。本项目不填入未运行的成绩，不把预印本当共识，也不将原作者的收益数字移植到自己的简历。
